# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.14.0] - Unreleased

### Added

- `docs/agent-guide/`: downstream tool-author guidance, with two Claude Code skills (`forensic-rs-tool-review`, `forensic-rs-new-tool`) and copyable repo-scaffolding templates (README, CHANGELOG, AGENTS.md, CI workflow) for tools built on top of the framework.
- Windows decompression algorithms: LZNT1, LZ77 and LZ77+Huffman
- Added ergonomic wrappers for VFS to accept `AsRef<Path>` for improved path flexibility.
- Categorized `ForensicError` variants: `Buffer`, `Format`, `Compression`, `DataAccess`, `Registry`, `Cast`, `Timestamp`, `Io`, `Other`
- Validation macros for ergonomic error construction: `ensure_buffer_size!`, `ensure_buffer_range!`, `ensure_format!`, `ensure_min_length!`, `ensure_max_length!`, `ensure_version!`, `compression_error!`, `invalid_offset!`, `missing_data!`
- `registry_key_not_found!` and `registry_value_not_found!` macros for registry-specific errors
- `compact_str::CompactString` used throughout error messages and metadata to avoid heap allocations for both short strings (inline storage) and `'static` strings of any length (via `CompactString::const_new`)
- Protocol-neutral capability API (`src/capabilities/`) for external MCP server integrations: caller-scoped tool and resource discovery, typed `CapabilityValue` inputs and outputs, native schemas, progress reporting, cancellation, and sanitized public errors.
- Feature-gated serde support for `CapabilityValue`, native schemas, tool descriptors, tool content/results, progress updates, and capability errors, with JSON round-trip compatibility tests for adapter-owned wire messages.
- Capability access controls: `AccessContext`, `AccessPolicy`, `AuditedAccessPolicy`, trusted `AccessAuditSink` records, execution-plan authorization, and path/channel/table/row guards for VFS, Registry, Event Log, and Database sources.
- Unified sniff-and-mount contract for nested evidence (`src/traits/format.rs`), replacing the short-lived `FileSystemFactory`/`ForensicDbFactory`/`EventLogReaderFactory`/`RegistryReaderFactory` traits (all introduced and removed within this same unreleased version — see Removed): "inside" a piece of evidence is really three different relationships — containment (a ZIP holds a file → a new `FileSystem`), interpretation (the same bytes read as a database/registry hive/event log), and embedding (a structured object like a PE exposes typed children) — and one `FormatFactory` trait (`name()`, `yields() -> MountKind`, `probe() -> ProbeScore`, `mount() -> Mounted`) now covers all three so a single resolver can recurse across them.
  - `Mounted` (`FileSystem`/`Registry`/`Database`/`EventLog`/`Object`/`File`): the result of one mount, cheaply `Clone`-able (an `Arc` clone).
  - `ProbeScore` (`No`/`Weak`/`Strong`/`Exact`): several factories can plausibly claim the same bytes; the resolver picks the highest score, tie-broken by factory name — never by registration order, which would make output depend on wiring.
  - `StructuredObject`: the embedding relationship — `children()`/`open_child()` plus an untyped `attributes()` map so a downstream parser (a PE parser, say) can surface facts core doesn't interpret.
  - `MountContext`: carries both the target's `FileSystem` and its `EvidenceLocator`, not just the opened bytes — an interpretation factory (SQLite, a registry hive) commonly needs companion files beside its target (WAL/SHM, `.LOG1`/`.LOG2`), which a bare byte stream can't express.
- `EvidenceLocator`/`LocatorSegment` (`src/core/locator.rs`): a structured, typed chain of hops (`Path`/`ArchiveEntry`/`Stream`/`Resource`/`Offset`/`Cell`/`Table`) locating evidence through nested containers, replacing ad hoc string-concatenated paths. Deliberately has no `FromStr` — an archive entry legitimately named `../../etc/passwd` can never be represented as a re-parseable path string. `to_source_key()` projects a locator into `SourceKey::Chain` for provenance.
- `MountResolver`/`MountResolverBuilder` (`src/core/resolver.rs`): drives `FormatFactory::probe`/`mount` across every registered factory, caches by `EvidenceLocator` (not by string path — a flat string cache can represent only one level of nesting), and enforces `Limits` shared across the whole resolution graph (nesting depth, total expanded bytes, entry count, expansion ratio) so many small containers can't each individually pass a check and still sum to an unbounded expansion. `probe_only()` offers the sniff step alone, for a "does this look like a container" hint without mounting.
- `Limits`/`SpillStore`/`MemorySpillStore` (`src/core/limits.rs`): resource budgets for hostile/untrusted evidence containers. `SpillStore` materializes forward-only content into something seekable; core ships only an in-memory implementation that refuses past its limit rather than silently spilling to disk — writing evidence-derived bytes to disk is an examiner's decision, not a library default.
- `Digest`/`DigestAlgorithm`/`ContentAddress` (`src/traits/digest.rs`): a trait-only content-hashing contract (no `sha2`/`blake3` dependency taken), letting `MountResolver` intern the same content reached through two different container chains and detect mount cycles, when a downstream crate supplies an implementation.
- `Requirement`/`Resolution`/`UnavailableReason`/`SchemaFingerprint`/`TargetSpec`/`KeySpec`/`ChannelSpec` (`src/traits/forensic.rs`) and `ParserDescriptor::requirements`: what a parser needs beyond a bare VFS/registry handle — a companion file, a database matching a schema subset, a secret — declared up front and introspectable without calling `open()`, for coverage reporting and pre-flight authorization. `SchemaFingerprint` matches a *required subset* of a database's tables/columns rather than a filename or exact schema, so a file named `History` dispatches by what it actually contains (and schema drift becomes detectable instead of a silent wrong-column read). `ParseContext::resolve()` resolves a self-contained `Requirement::File` via a VFS glob; `ParseContext::mount()` mounts an already-located target through the run's `MountResolver`.
- `Secret`/`SecretKind`/`SecretRequest`/`SecretProvider` (`src/secrets.rs`): externally supplied key material for decrypting evidence-derived ciphertext (a DPAPI-protected credential, a BitLocker volume). `Secret` implements none of `Debug`/`Display`/`Serialize`/`Clone`/`Deref` — enforced by `trybuild` fixtures in `tests/compile_fail/` — and zeroizes its backing buffer on drop. Core never implements `SecretProvider` with a real backend and never caches or persists what one returns; a failed decryption is meant to still emit the record (ciphertext present, marked undecrypted) with a `Finding`, never a silent skip.
- `TriageSources::mount_resolver()`/`TriageSourcesBuilder::mount_resolver()` and `TriageSources::secrets()`/`TriageSourcesBuilder::secrets()`: optional, purely additive attachment points for the above.
- `Investigation`/`InvestigationId`/`TenantId` (`src/investigation.rs`): a small, deliberately opaque identity for an investigation — id, tenant, optional examiner/opened-at/metadata — no status, workflow, or case management. Its job is to give provenance and coverage reporting a real identity and examiner to seal against; before this, `case_id` was a bare `String` in example tool schemas with no typed equivalent anywhere in the crate.
- `EvidenceSet`/`EvidenceItem`/`EvidenceItemId` (`src/evidence.rs`): an ordered set of typed evidence items (a host's triage collection, a disk image, a memory capture) under one `Investigation`, closing the gap where `TriageSources` — one VFS, one registry, nothing else — could not express "this investigation has three hosts, one of them also with a memory image." Each `EvidenceItem` resolves lazily into the `TriageSources` view a pipeline run actually consumes, via a repeatable (not one-shot) factory closure cached after its first successful call, so a transient resolution failure can be retried rather than permanently poisoning the item. `kind: MountKind` reuses the same vocabulary `FormatFactory` uses one level down, inside a single container. `TriageSources` is now `Clone` (every field is an `Option<Arc<..>>` or `Copy` value) to support this caching.
- `CollectionManifest`/`ToolIdentity`/`CollectionError`/`StaticCollectionManifest` (`src/collection.rs`): what a collection tool (KAPE, CyLR, Velociraptor, UAC, `.frtriage`) says it did — which tool, when, by whom, against what target list, and what it itself failed to collect. `Acquisition::RemoteCollection` alone records only *that* a collector ran, never *when*/*with what*/*by whom*/*against which target list*, so `SourceKind::Triage`'s "absent may mean not collected rather than not present" distinction was previously unanswerable. Real KAPE/CyLR/Velociraptor/UAC log parsers are downstream; core ships the trait plus `StaticCollectionManifest`, a plain in-memory implementation for tests and simple formats.
- `CoverageReport`/`CoverageGap`/`CoverageGapReason` (`src/coverage.rs`): `CoverageReport::compute(manifest, fs)` checks a `CollectionManifest`'s declared targets against what's actually present in the evidence (via `FileSystemExt::glob`), attributing each miss to a logged `CollectionError` when the manifest recorded one, else `CoverageGapReason::NotFound`. Converts "I found nothing" into "I found nothing, and here is exactly what I could not look at, and why."
- `HostProfile` (`src/host_profile.rs`): a host's identity facts (computer name, system root, OS version, users) resolved in one pass, every field `Option<Tracked<T>>` so an unresolved fact stays unresolved rather than defaulting — a missing computer name never becomes an empty string, and (since no registry-based timezone resolver exists yet — `windows::timezone` is itself deferred) a missing timezone can never silently become UTC, because the `timezone` field is always `None` today by construction. `HostProfile::resolve_from_context` is a convenience over a pipeline `ParseContext`'s registry and provenance store.
- `EventId`/`TimelineStore`/`InMemoryTimelineStore`/`TimelineRecordSink`/`InsertOutcome` (`src/pipeline/timeline.rs`): a timeline that is actually a timeline. `TimelineSink` tracks earliest/latest bounds and counts but never stores a record; `JsonlTimelineSink` appends in emission order and explicitly declines to sort — so the crate named after triage had no timeline. `EventId` is a stable identity derived from `(evidence_id, source_key, locus, projection_kind)`, deterministic (FNV-1a, not `RandomState`) so re-processing identical evidence converges on the same event identities instead of minting new ones every run — `ProvenanceId` can't serve this role, being a dense per-run index. `TimelineStore` is the trait (`insert`, ordered `iter_ordered`, dedup by `EventId`); `InMemoryTimelineStore` is the only implementation core ships (bounded by memory, no spill-to-disk — a `sqlite`/`parquet`-backed store is downstream). `TimelineRecordSink` is the `TriageSink` that was previously left as an exercise ("implement a custom `TriageSink` to write findings to disk"): it resolves each record's `SourceKey` from a *shared* `ProvenanceStore` (requires the `ParallelPipelineBuilder::context`/`TriagePipelineBuilder::context` fix above), and stores full ordered, deduped records. `Locus` isn't yet attached to individual records by any pipeline stage, so `EventId` uses `Locus::Api` uniformly at the sink layer for now — full byte-level precision needs a future projector stage. The shared `fnv1a64` hash (previously private to `SchemaFingerprint`) moved to `crate::core` so both users share one implementation.
- `EntityId`/`EntityKind` (`src/entity.rs`): content-derived, stable-across-runs identity for the subjects an investigation correlates evidence about (`Host`, `User`, `Executable`, `File`, `Process`, `NetworkEndpoint`, `RegistryKey`, `ScheduledTask`, `Service`). Deliberately never a sequence number — two artifacts describing the same host/user/executable must resolve to the same id whether parsed in the same run or a collection wave weeks apart. Per-kind constructors (e.g. `EntityId::executable_by_hash`/`executable_by_path`) document how each kind's identity is derived; `Executable`/`File` prefer a `ContentAddress` hash over a bare path when one is available.
- `FactStore`/`InMemoryFactStore`/`ObservationOutcome`/`FactRecord`/`FactObservation` (`src/fact_store.rs`): cross-artifact corroboration — the direct payoff of the provenance model, previously unexercised by any output path. Every fact recorded about an `EntityId` via `FactStore::observe` is an append-only observation; agreeing observations fold their `ProvenanceId`s into one `MergeReason::CrossSourceCorroboration` node via `ProvenanceStore::merge`, and disagreeing ones are never resolved by silently picking a side — both values are retained (`FactRecord::is_disputed`), and the caller gets back an `AnomalyDetail` flagged `AnomalyFlags::SOURCE_DIVERGENCE` to fold into its own output. Documented limitation: `ProvenanceStore::confidence`'s chain folding takes the worst case across a merge chain (the right call for `Reconciliation`), so corroboration today surfaces *that* independent sources agree without numerically boosting confidence above the weakest one — giving `MergeReason` its own folding semantics is a deliberately separate, not-yet-made change.
- `ParallelPipelineBuilder::context(TriageContext)`: a pipeline-wide default context, adopted by every `StandardParallelTask`/`AnalysisModule` that doesn't set its own via `ParallelPipelineTask::adopt_shared_context` (new, default no-op trait method). Fixes a correctness gap where, without this, each task/module that left `.context()` unset fell back to its own independent `TriageContext::default()` — and therefore its own independent `ProvenanceStore` — so a record reaching a sink on the main thread carried a `ProvenanceId` no single store handle could resolve; `data.confidence(&store)` was effectively unavailable in parallel mode. `TriageContext` is now `Clone` (deliberately: `forensic`/`shared` clone as independent owned data, but `provenance_store` is an `Arc` handle, so every clone shares the same underlying store). `ParallelPipeline::provenance_store()` and `ParallelPipelineResult::provenance_store` expose the shared store, when one was configured.
- Native `ResourceProvider` implementations for `VfsProvider`, `RegistryProvider`, `EventLogProvider`, and `DatabaseProvider`; `BridgeResourceProvider` remains available for legacy third-party bridge providers.
- `EventLogReader` trait (`src/traits/events.rs`): abstract interface for querying Windows event logs with filtering, pagination, and fallible iteration. Includes `EventLogQuery` builder (filter by event ID, time range, provider, severity level, channel), `EventLogIterator` (fallible `next() -> ForensicResult<Option<EventRecord>>`), `EventRecord` (record_id, event_id, timestamp, provider, channel, level, computer, user_sid, extensible `data` map), and `EventLevel` enum (Critical=1..Verbose=5). `EventRecord` implements `Into<ForensicData>` mapping standard fields to ECS names.
- `EventLogReader` ergonomic wrappers on `dyn EventLogReader`: `query_all()` and `query_channel(channel)`.
- `TestingEventLogReader` in `src/utils/testing.rs`: in-memory mock implementing `EventLogReader` for unit testing. `basic_event_log()` convenience constructor populates sample Security and System events.
- `ForensicBridge` module (`src/bridge/`): channel-based multi-threaded bridge exposing all artifact domains as navigable trees for UI consumers (VSCode extensions, web frontends, etc.):
  - `ForensicProvider` trait: object-safe interface with `name()`, `children()`, `read()`, `metadata()` methods supporting pagination and cooperative cancellation.
  - `CancellationToken`: thread-safe `Arc<AtomicBool>` cooperative cancellation for long-running operations.
  - `BridgeValue`: recursive value enum (`Null`, `Bool`, `I64`, `U64`, `F64`, `Text`, `Timestamp`, `Binary`, `Array`, `Map`). Implements `From<Field>` and `From<RegValue>`. Serializes to JSON via serde feature.
  - `NodeEntry` / `NodeType`: tree node model (`Container`, `Leaf`, `Virtual`).
  - `BridgeRequest` / `BridgeResponse`: channel-based protocol (ListProviders, Children, Read, Metadata, Actions, Shutdown).
  - `BridgeClient`: cloneable `Send` handle to the bridge worker thread. Methods: `list_providers()`, `children()`, `children_page()`, `children_cancellable()`, `read()`, `metadata()`, `actions()`, `shutdown()`, configurable timeout via `request_timeout()`.
  - `ForensicBridgeBuilder` / `ForensicBridge`: builder spawns a dedicated worker thread owning all providers; returns a `BridgeClient`.
  - `RegistryProvider`, `VfsProvider`, `EventLogProvider`, `DatabaseProvider`: concrete `ForensicProvider` implementations wrapping each artifact trait. `RegistryProvider`/`VfsProvider` hold their `Arc<dyn Registry>`/`Arc<dyn FileSystem>` directly (both traits are `&self`-based, so no lock is needed); `EventLogProvider`/`DatabaseProvider` still wrap their reader behind a `Mutex`. `VfsProvider` now dispatches its registered hooks from `children()`/`read()`, the same way `RegistryProvider` already did — a hook registered via `add_hook()` on a `VfsProvider` was previously never consulted.
  - `ProviderHook` trait (`src/bridge/hooks.rs`): postprocessing hooks that inject virtual parsed children into bridge tree nodes (e.g., parsed shellbag data inside registry binary values). Two-stage matching: `matches_path()` (fast) then `matches_value()` (content inspection). Virtual path convention: `[hookname]` bracketed segment avoids collisions with real children. `virtual_children()` now takes a `virtual_path` parameter (`""` for the hook's own root, a nested sub-path otherwise) so hooks can express real multi-level trees instead of only ever listing their root — mirrors how `read_virtual()` already self-routes on its `virtual_child` parameter.
  - Hook utilities: `virtual_segment(name)`, `is_virtual_segment(s)`, `split_virtual_path(path)`, `inject_hook_children()`, `collect_hook_actions()`.
  - `ForensicProvider::actions()` / `ResourceProvider::actions()`: per-node discovery of applicable command/tool IDs, so parsers and analyzers can attach custom commands to specific nodes/leafs (via `ProviderHook::action_ids()`/`virtual_action_ids()`) instead of being limited to the one default read. Purely a discovery link to already-registered `ForensicTool` IDs — invocation still goes through `CapabilityRegistry`'s existing `invoke_tool()`. `ScopedCapabilityRegistry::list_node_actions()` surfaces this on the capabilities/MCP side, filtered by the same access policy as `list_tools()`/`list_resources()`.
  - `TestingProviderHook` (`src/utils/testing/hooks.rs`) is now nesting-aware (`with_child(at, entry)` keyed by virtual path) and gained `with_action()`/`with_virtual_action()` for testing the new action-discovery methods.
- `ForensicTimestamp`: Bitpacked u64 timestamp (8 bytes, microsecond precision, year 0-4095) with constructors for Windows FILETIME, Unix seconds/millis/micros, OLE Automation dates, WebKit/Chrome, HFS+, and Cocoa timestamps. Full bidirectional conversion with `Filetime`.
- **Breaking**: `ForensicTimestamp` is now the canonical 16-byte, 16-byte-aligned timestamp with nanosecond precision, validated parts, optional UTC-offset metadata, provenance flags, and portable endian-specific byte encodings. `Timestamp128` aliases it. Framework timestamp carriers, including `Field::Date`, database values, VFS metadata, activities, timelines, event records, and registry metadata now retain this representation. `Filetime` remains an input-format adapter.
- `VMetadata` timestamps migrated from `Option<usize>` (seconds) to `Option<ForensicTimestamp>` (microsecond precision).
- **Breaking (RFC 0001 core trait redesign)**: `FileSystem`/`Registry` are rebuilt around a minimal, mechanical, `Send + Sync`, `&self`-based core trait per resource, an object-safe blanket "ext" trait for ergonomics, opt-in capability traits, and factory traits for construction. This replaces the `&mut self`-based `VirtualFileSystem`/`RegistryReader` traits entirely (not deprecated — removed) and is the headline breaking change of this release:
  - `FPath`/`FPathBuf` (`src/core/path.rs`): a `/`-normalized, drive-aware, case-preserving evidence-path type distinct from `std::path::Path` (which carries host, not evidence, semantics). Case-insensitive comparison goes through `path_eq(a, b, CaseSensitivity)`, driven by the filesystem being analyzed, never by the path text itself.
  - `FileSystem` (core, `&self`, `Send + Sync`): `open()`, `metadata()`, `read_dir()` (returns a lazy `Box<dyn Iterator<Item = ForensicResult<DirEntry>>>`), `source() -> SourceKind` (`Live`/`Image`/`Triage`/`Memory` — replaces the old bare `is_live(): bool`, which couldn't distinguish "absent from the evidence" from "never collected"), `case_sensitivity() -> CaseSensitivity`. `Arc<dyn FileSystem>` can now be shared across worker threads, which is what makes genuinely parallel image scanning possible — the old `&mut self` design could not do this.
  - `FileSystemExt` (blanket-impl'd convenience layer): `read_all()`, `exists()`, `walk()` (a real lazy, `&self`-based streaming DFS with loop/hardlink detection via `FileId`, replacing `walk_dir`/`walk_dir_strict`/`walk_dir_best_effort`), `glob()`/`glob_iter()` (metachar-prefix-scoped, never enumerates a whole drive for a pattern like `C:/Users/*/NTUSER.DAT`).
  - `DirEntry`, `VMetadata` (now carrying `MacbTimes`, `FileAttributes`, optional `FileId`, `allocated_size`), `AlternateStreams` and `Unallocated` capability traits (opt-in via `FileSystem::as_streams()`/`as_unallocated()`), `MountTable`/`OverlayFs` (longest-prefix and first-match layered filesystem composition). (An early `FileSystemFactory` trait for sniffing and mounting nested filesystems was introduced here and superseded before release by the unified `FormatFactory` — see below.)
  - `Registry` (core, `&self`, `Send + Sync`): `root(PredefinedHive)`, `open_raw`/`close_raw`/`read_raw`/`values_raw`/`keys_raw`/`info_raw`, all keyed by an opaque, non-`Clone` `RawKey`. `RegKey<'r>` is a lifetime-tied RAII guard (private fields, `!Send`/`!Sync`) that closes on drop — a `RegKey` cannot outlive its `Registry`, cannot cross readers, and `RawKey` cannot be duplicated, all enforced at compile time (proven by `trybuild` fixtures in `tests/compile_fail/`). This replaces `RegKeyHandle`, which was move-only but not lifetime-tied to its reader, making cross-reader misuse and use-after-reader-drop *runtime* errors instead of compile errors.
  - `RegistryExt` (blanket convenience layer): `key(path)`/`value(path, name)`/`keys_at(path)`/`values_at(path)` take a single hive-prefixed path string (`"HKLM\Software\..."`, accepting both short and long hive forms, case-insensitively) instead of a separate `(hive, key_path)` pair; `for_each_user_hive()` expands `*` over `HKEY_USERS` SIDs.
  - `PredefinedHive` replaces `RegHiveKey`; the old `Hkey(isize)` raw-seed-handle variant has no equivalent — seeding a backend from an externally-supplied raw handle is now a backend-constructor concern, not part of this enum.
  - `windows::system_root()`, `windows::users()`, `windows::build()` (`src/traits/registry/windows.rs`): free functions replacing the old `RegistryReader::get_system_root()`/`list_users()`/`windows_build()` default trait methods — Windows analysis semantics derived from registry operations, not registry primitives. `windows::users()` returns a richer `UserProfile { sid, profile_path, name }` correlating `ProfileList` against `HKEY_USERS`; `windows::build()` returns a richer `WindowsVersion { build, major, minor, display_version, product_name }` instead of a bare `u32`.
  - `RegValue` expanded from 6 to 13 variants (now `#[non_exhaustive]`): added `DWordBigEndian`, `Link`, `ResourceList`, `FullResourceDescriptor`, `ResourceRequirementsList`, `Unknown { ty, data }` (preserves unrecognized/corrupt values as evidence instead of discarding them). `RegValue::raw_bytes()` gives the on-disk byte representation uniformly across every variant.
  - `RecoverDeleted` capability trait (`deleted_keys()`/`deleted_values()`) and `KeyEntry.allocated: bool` — plumbing for future hive-slack recovery; no backend implements it yet.
  - Every in-repo consumer (`TriageSources`, `ParallelPipeline`, the `capabilities` authorization layer, the `bridge` providers, testing factories) now holds `Arc<dyn FileSystem>`/`Arc<dyn Registry>` instead of `Box<dyn VirtualFileSystem>`/a `Mutex`-wrapped registry reader — construction is `Arc::new(...)`, not `Box::new(...)`, and sharing a source across parallel workers is a plain `Arc::clone()`.
  - Removed entirely (not deprecated): `VirtualFileSystem`, `VDirEntry`, `RegistryReader`, `RegHiveKey`, `RegKeyHandle`, `RegistryVisit`, `RegistryOpenOptions`, `RegistryAccess`, `Wow64View`, `FromRegistryValue`, `RegistryKeyInfo`, the `HKLM`/`HKU`/`HKCU`/`HKCR`/`HKC` constants, and `TestingRegistry`'s `mount_file()`/`mount_fs()` stubs.
- **Breaking**: `RegistryError::{KeyNotFound, ValueNotFound}.key` is now `PredefinedHive` instead of `RegHiveKey`.
- **Breaking**: `ForensicError` and its 7 category enums (`BufferError`, `FormatError`, `CompressionError`, `DataAccessError`, `RegistryError`, `CastError`, `TimestampError`) are now `#[non_exhaustive]`.
- `ForensicError::with_path()`/`with_offset()`/`path()`/`offset()`: attach and read back an `FPathBuf` and/or byte offset on any error via an additive `Contextualized` wrapping variant, without restructuring existing constructors.
- `ParallelPipeline::run_with_cancellation()`: cooperative cancellation for built-in parallel tasks using `CancellationToken`.
- `ArtifactParserFactory` (`src/traits/forensic.rs`), replacing `ArtifactParser`: a stateless, `&self` parser factory shared behind one `Arc` across the serial pipeline, every parallel worker, and every `AnalysisModule` that needs it. `open()` returns a `ParserRun`, either `Pull(ArtifactStream)` (an owned iterator, the common case — no lifetime tied to `self` or to `TriageSources`) or `Push(PushDriver)` (a closure that drives its own loop and pushes into a `ParserOutput`), the sanctioned way to express a parser backed by a reader that returns borrowed cursors (a registry key, a database row cursor, an event-log iterator) without a self-referential struct or an `Option<Reader>` field.
- `ParserDescriptor` (`id`, `title`, `description`, `version`, `artifacts`): a parser's stable identity and artifact declaration, returned by `ArtifactParserFactory::descriptor()` as a `&self`-borrowed value — no per-call allocation, and a factory can hold a `static` descriptor.
- `ParseContext` (`src/pipeline/context.rs`): what a parser sees during one `open()` call — `sources()`/`vfs()`/`registry()`, `host()`, `acquisition()` (explicit override, else derived from the VFS's `SourceKind`, else the conservative `Acquisition::LiveApi` floor — never defaults to `ImageRead`), `cancellation()`, and `register_source(SourceKey) -> SourceHandle`. `register_source` interns against **this run's own** `ProvenanceStore`, closing the class of bug where a caller-injected `SourceHandle` minted against a different store than the one the pipeline resolves confidence against would silently misattribute provenance (`ProvenanceId` is a dense index, so a foreign handle can resolve to a plausible-looking *wrong* record, not just degrade to `Confidence::Unknown`).
- `ParserRegistry` (`src/pipeline/registry.rs`): ID-keyed store of parsers, mirroring `CapabilityRegistry` — the backing store `AccessRequirements::parser(id)` had been authorizing against nothing.
- `OwnedRegKey` (`src/traits/registry/raw.rs`): `Arc`-owning counterpart to `RegKey<'r>` for a parser that must own its reader (rather than borrow one handed to it by lifetime) and still deliver an owned `ParserRun::Pull` stream. Same guarantees as `RegKey`, enforced by ownership instead of a lifetime parameter.
- `impl From<SourceKind> for Acquisition` and `TriageSourcesBuilder::acquisition()`/`TriageSources::acquisition()`: the explicit-override-else-derived resolution `ParseContext::acquisition()` uses.
- `TriagePipeline::run_with_cancellation()`: cooperative cancellation for the serial pipeline (previously parallel-only), checked before each parser and between records, and exposed to `Push` parsers via `ParseContext::cancellation()`.
- `TriagePipelineBuilder::parsers_from(&ParserRegistry)` / `ParallelPipelineBuilder::parsers_from(&ParserRegistry)`: bulk-register every factory currently in a registry.
- `ForensicData` helper methods: `remove()`, `contains_key()`, `get_date()`, `extend_from()`, `len()`, `is_empty()`.
- `ForensicContext::metadata`: Extensible `BTreeMap<Text, Text>` for custom analysis context.
- `From<bool>`, `From<Filetime>`, `From<ForensicTimestamp>` implementations for `Field`.
- `ProgramExecution` enriched with `arguments`, `working_directory`, `run_count` fields.
- `FileSystemActivity::Rename`, `FileSystemActivity::Read`, `FileSystemActivity::Write` variants.
- `ForensicActivity::extras`: Extensible `BTreeMap<Text, Text>` for additional context.
- `ForensicData::anomalies()`/`confidence(&ProvenanceStore)`: a record now carries the `Anomalies` folded in by `set_parsed`, instead of the caller having to thread them through separately.
- `Anomalies::merge()`: folds another instance's flags/details into this one.
- `CapabilityValue` conversions for `Confidence`, `Anomalies`, and `Finding` (`src/capabilities/value.rs`): pipeline findings and evidentiary confidence/anomaly data can now flow into MCP tool/resource output without every server author hand-rolling the mapping.
- `FindingCategory::ProcessingError` and `Finding::from_error()`: a crashed parser/enricher/analyzer now produces a finding (evidence went unexamined), not just a log line — `TriagePipeline`/`ParallelPipeline` do this automatically for every stage failure.
- `AnomalyTally` (`src/pipeline/finding.rs`): accumulates per-flag anomaly counts across a parser run and lowers them into one aggregate `Finding` per flag observed, instead of one finding per anomalous record. Wired automatically into `TriagePipeline`/`ParallelPipeline`.
- `Walk`/`WalkOptions::skip_errors`: an unreadable subtree is now yielded once as a `ForensicResult::Err` item (in addition to the existing `warn!` log) instead of being silently swallowed.
- Widened the `Artifact` taxonomy (`src/artifact.rs`) with common artifacts: `WindowsArtifacts::{JumpLists, LnkFiles, Bits, WmiRepository, PowerShellHistory, RdpCache, Timeline}`, `RegistryArtifacts::{AmCache, Services, UserAssist, Bam, TypedPaths, RecentDocs}`, `WindowsEvents::PowerShell`, `LinuxArtifacts::{Journal, Accounts, Ssh}`, and a real `MacArtifacts` taxonomy (`FsEvents`, `Spotlight`, `UnifiedLogs`, `Tcc`, `LaunchAgents`, `LaunchDaemons`, `KnowledgeC`) replacing the previous `Other`/`Unknown`-only stub.

### Changed

- **Breaking**: `TriageSources` no longer stores one pre-opened `EventLogReader` or `ForensicDb`. Parsers discover event-log and database files through the VFS and open each one with an injected reader factory. This keeps evidence acquisition separate from artifact decoding.
- **Breaking**: The crate now uses Rust 2024 edition and requires Rust 1.85 or newer.
- **Breaking**: `ArtifactParser` (the `&mut self`, `fn parse<'a>(&'a mut self, sources: &'a mut TriageSources) -> ForensicResult<Box<dyn Iterator<...> + 'a>>` trait) is removed entirely, not deprecated — replaced by `ArtifactParserFactory` (see Added, above). The old signature tied a parser's own lifetime to `TriageSources`' lifetime, forcing any parser that discovers and opens its own reader (rather than borrowing one already open in `TriageSources`) into a self-referential `Option<Reader>` field plus `&mut self` self-mutation to fake lazy initialization. `RegistryParser` (zero implementors, zero consumers) is removed with it. Migration: fold `name()`/`description()`/`version()`/`supported_artifacts()` into one `ParserDescriptor`; move `&mut self`-held construction state into a local inside `open()`; a parser that returned `Box::new(records.into_iter())` returns `ParserRun::pull(records.into_iter())` unchanged. `TriagePipelineBuilder::parser()`/`StandardParallelTaskBuilder::parser()`/`AnalysisModuleBuilder::parser()`/`ParallelPipelineBuilder::parser()` now all take `Arc<dyn ArtifactParserFactory>` instead of `Box<dyn ArtifactParser>` — the same instance is now shared, not reconstructed, across every worker/module that uses it.
- **Breaking**: `ParallelPipelineBuilder::parser_factory()`/`parser_factory_with_artifacts()` and the `ParserFactory` type alias are removed — auto-matching now compares each registered parser's `ParserDescriptor::artifacts` directly (no construction needed to read metadata), via the new `ParallelPipelineBuilder::parser(Arc<dyn ArtifactParserFactory>)`.
- **Breaking**: `TriagePipeline::run()`/`TriagePipelineBuilder::parser()` — `run()` now takes `&TriageSources` instead of `&mut TriageSources` (existing `.run(&mut sources)` call sites still compile; `TriageSources` never had a `&mut self` method, so the old signature was a false constraint).
- **Breaking**: `utils::testing::{TestParser, TestParserBuilder}` renamed to `TestParserFactory`/`TestParserFactoryBuilder` and reshaped onto `ArtifactParserFactory` — the builder API (`description()`, `version()`, `with_artifact()`, `with_record()`, `with_records()`, `with_result()`, `with_results()`, `parseable()`) is unchanged, plus a new `push_mode(bool)` to exercise `ParserRun::Push`. `open()` now clones its fixture records instead of draining them, so the same built factory can be `open()`ed more than once (an `Arc`-shared factory used by several parallel modules previously would have silently yielded nothing on the second call).
- **Breaking**: `IntoTimeline` iterator item changed to `ForensicResult<TimelineData>`.
- **Breaking**: `IntoActivity` iterator item changed to `ForensicResult<ForensicActivity>`.
- **Breaking**: `Field` `TryInto` impls now return `ForensicError` instead of `&'static str`.
- **Breaking**: `VMetadata::created()`, `accessed()`, `modified()` now return `ForensicTimestamp` instead of `usize`.
- **Breaking**: Registry keys are opened and read through `RegKey<'r>`, a lifetime-tied RAII guard that closes exactly once on drop and cannot outlive the `Registry` (or reader) that opened it — see the RFC 0001 entry above.
- `VfsProvider` metadata now returns `BridgeValue::Null` for unavailable timestamps instead of fabricating Unix epoch values.
- `Field` conversions to `u64` and `i64` now reject lossy signed, floating-point, non-finite, and out-of-range conversions.
- **Breaking**: `Analyzer::analyze()`/`finalize()` now take an `out: &mut Vec<Finding>` accumulator and return `ForensicResult<()>`, instead of returning `ForensicResult<Vec<Finding>>`. Findings pushed to `out` before a `?` bails out with `Err` are still delivered to the sinks — previously they were discarded along with the error.
- **Breaking**: `ForensicData::set_parsed()` now folds the value's `Anomalies` into the record (see `Self::anomalies()`) and returns only `ProvenanceId`, instead of handing back a droppable `(Anomalies, ProvenanceId)` tuple. `Parsed<T>` is now `#[must_use]`.
- **Breaking**: `Artifact`, `WindowsArtifacts`, `WindowsEvents`, `RegistryArtifacts`, `LinuxArtifacts`, `LinuxService`, `MacArtifacts`, `CommonArtifact`, and `WebBrowsingArtifact` are now `#[non_exhaustive]`, so this catalog can keep growing without every addition being a semver-breaking change for downstream `match` expressions. Any exhaustive match on these enums outside this crate now needs a wildcard arm.

### Removed

- `FileSystemFactory` (`traits::vfs`) and `traits::factories` (`ForensicDbFactory`, `EventLogReaderFactory`, `RegistryReaderFactory`): all four were introduced earlier in this unreleased version and are removed before release, superseded by the unified `FormatFactory` (see Added). They had zero production consumers in the crate at the time of removal.
- `src/notifications/` (`Notifier`, `Notification`, `NotificationType`, `Priority`, `notify!`/`notify_low!`/`notify_info!`/`notify_informational!`/`notify_medium!`/`notify_high!`/`notify_critical!`, `initialize_notifier()`, `testing_notifier_dummy()`): removed entirely, not deprecated. It was a thread-local channel that silently dropped every message unless a receiver was explicitly installed (`Notifier::default()` opened a channel and immediately dropped the receiver), had zero call sites in `src/`, and duplicated `Finding`/`FindingSeverity`/`FindingCategory` less safely. Forensic alerts go through `Finding` (routed to every `TriageSink`, can't silently no-op) instead.

### Fixed

- Binary offset validation is overflow-safe, and new fallible endian-explicit unpack helpers prevent truncated artifact data from panicking.
- `ForensicError` now preserves original `std::io::Error` values created through `From<std::io::Error>` or `io_error_with_source()`, exposing them through `Error::source()`.
- Parallel pipeline worker panics are reported as task errors without preventing healthy tasks from completing.
- `Artifact`'s `Display`/`FromStr` string protocol (`src/artifact.rs`) no longer silently loses or mangles data on round-trip: `RegistryArtifacts::ShimCache` displayed as `"InitD"`; `Artifact::MacOs` displayed with tag `"Mac::"` while parsing only recognized `"MacOs::"` (every macOS artifact silently became `Artifact::Other`); `LinuxArtifacts::Unknown` displayed as `"Log::Unknown"`; `LinuxArtifacts::Service(_)` failed to parse back (wrong substring was forwarded to the nested parser); and free-form `Other(String)`/bare unrecognized tags without a `"::"` separator were coerced into `Unknown` or an empty string instead of preserving the original text (`WindowsArtifacts`, `LinuxArtifacts`, `CommonArtifact`, `OtherOS`).
- `utils::win::decompress`: `CompressionAlgorithm::CompressionFormatLznt1` was dispatched to the plain-LZ77 decoder (there was no LZNT1 decoder at all) and `CompressionFormatXpress` to the Huffman decoder instead of plain LZ77 — both swapped. Added a real `lznt1` decoder (verified against libyal/libfwnt's documented LZNT1 algorithm) and fixed the dispatch. Also fixed `CompressionFormatNone`, which panicked via `Vec::copy_from_slice` unless the output buffer already matched the input length.
- Added `Registry::open_child_raw` (and `RegKey`/`OwnedRegKey::open_child`) for reopening an already-enumerated child by its exact, literal name. `open_raw`/`.open()` treat their `name` argument as a possibly multi-segment path and split on `/`/`\`, which silently mis-resolves a child whose *own* name legitimately contains those characters (e.g. AmCache `InventoryDriverBinary` entries, keyed by full lowercase driver file paths) — every such child previously failed to open with a spurious `KeyNotFound`. Defaults to `open_raw` for backends that don't override it.

### Deprecated

- `ForensicError::bad_format_str()` / `bad_format_string()` — use `ensure_format!` macro instead
- `ForensicError::missing_str()` / `missing_string()` — use `missing_data!` macro instead
- `VMetadata::created()`, `accessed()`, and `modified()` epoch-substituting accessors; use their corresponding `*_opt()` methods.
- Legacy `u16_at_pos`, `u32_at_pos`, `u64_at_pos`, and big-endian variants; use `read_u*_le_at()` or `read_u*_be_at()`.
